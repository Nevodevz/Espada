# Карточка клиента как в AmoCRM и задачи по лидам — дизайн

Дата: 2026-11-20 · Статус: на утверждении
Заменяет §5.3 (часть 3) в `2026-11-19-sales-crm-overhaul-design.md`.

## 1. Зачем

Интерфейс ощущается перегруженным. Самое тяжёлое место — карточка лида: 12 блоков
в одну колонку, история размазана по трём блокам («Этапы», «История касаний»,
«Таймлайн»), чат WhatsApp — отдельным блоком, в шапке 5–6 кнопок. Чтобы понять,
что делать с клиентом дальше, приходится листать.

Отдел продаж просит карточку «как в AmoCRM» и задачи по лидам: «позвонить»,
«недозвон», «перезвонить в такое-то время».

Успех: продажник открывает лида и сразу видит, какая задача на нём и что было
раньше; отмечает звонок одним кликом и тут же ставит следующий шаг; утром
открывает «Мои задачи» и идёт по списку.

## 2. Решения, принятые с пользователем

- **Раскладка A**, две колонки:
  - слева — поля клиента и сделки, редкие блоки свёрнуты;
  - справа — одна лента событий, открытые задачи сверху, внизу одно поле ввода
    с вкладками «WhatsApp / Примечание / Задача».
- **Задачи — отдельная сущность CRM** (а не карточки личных досок): личные
  канбаны не засоряются звонками.
- **Поток звонка:**
  - постановка задачи — тип, быстрое время, ответственный, комментарий;
  - в срок задача сверху ленты с кнопками «Дозвонился / Недозвон / Перенести»;
  - «Недозвон» пишет запись в ленту, наращивает счётчик и сразу предлагает
    «Перезвонить через 2 часа»;
  - «Дозвонился» — короткий итог и предложение сменить этап и/или поставить
    следующую задачу;
  - у открытого лида всегда должна быть следующая задача, иначе подсветка
    «Нет задачи».
- Значения по умолчанию, утверждённые пользователем («всё подходит»):
  - быстрые сроки — через 15 мин / через 1 час / сегодня вечером / завтра
    утром / своя дата;
  - после недозвона — «Перезвонить» через 2 часа.
- **5 недозвонов подряд** → система предлагает «Минус» с причиной «Не выходит
  на связь». Это моё решение, пользователь его не оспорил. Решает человек,
  автоматического перевода нет.

## 3. Цели, не-цели, анти-цели

**Цели**
- Новая карточка лида (раскладка A) со всей текущей функциональностью: этапы и
  переходы, финансы и график оплат, встречи, файлы, проект, WhatsApp, архив,
  редактирование.
- Задачи по лидам с напоминаниями, счётчиком недозвонов и страницей
  «Мои задачи».
- Задачи видны на доске (ближайшая задача, просрочка, «Нет задачи», 📵×N) и
  в колокольчике.
- Старое поле «следующее действие» переезжает в задачи и исчезает из
  интерфейса.

**Не-цели (сейчас)**
- Переделка доски целиком, меню слева, других страниц.
- Telegram-напоминания: точку отправки закладываем, сам бот позже.
- Интеграция с телефонией (звонки «в один клик», записи).
- Inline-редактирование полей в карточке: остаётся модалка «Изменить».

**Анти-цели**
- В карточке пропала какая-то функция, которая есть сейчас: финансы, оплаты,
  файлы, касания, встречи, архив.
- Задачу можно потерять: просроченная не видна ни в карточке, ни на доске, ни
  в колокольчике.
- Лента тормозит на лиде с большой перепиской (нужна пагинация).
- Продажник видит и закрывает чужие задачи без прав.

## 4. Подходы (выбран 1)

| | Итог |
|---|---|
| **1. Отдельная таблица `lead_tasks`** ✅ | Тип, точное время, результат, счётчик недозвонов; страница «Мои задачи». Личные доски не трогаем |
| 2. Переиспользовать `Task` личных досок | Готовы календарь и уведомления, но личная доска продажника превращается в очередь звонков, а «Недозвон/Перенести» туда не ложатся |

Лента собирается **на сервере** одним эндпоинтом с курсорной пагинацией: так
клиенту не нужно склеивать пять запросов, и порядок событий гарантирован.

## 5. Дизайн

### 5.1 Модель задач

Таблица `lead_tasks`:

| Поле | Тип | Смысл |
|---|---|---|
| `id` | int PK | |
| `lead_id` | FK leads, CASCADE, index | |
| `kind` | str: `call` \| `message` \| `meeting` \| `other` | Позвонить / Написать / Встреча / Другое |
| `due_at` | datetime tz, index | срок (UTC; вводится по Бишкеку) |
| `assignee_id` | FK users, SET NULL, index | ответственный |
| `created_by` | FK users, SET NULL | |
| `comment` | text | что сделать |
| `status` | str: `open` \| `done` \| `canceled` | |
| `result` | str \| null: `connected` \| `no_answer` \| `rescheduled` \| `done` \| `auto_canceled` | итог |
| `result_note` | text | итог звонка |
| `completed_at`, `completed_by` | | |
| `created_at` | | |

- **Счётчик недозвонов не хранится** (принцип проекта «производное
  вычисляется»). Он равен числу задач `kind='call'` с `result='no_answer'`,
  завершённых после самого позднего из событий:
  - последней задачи с `result='connected'`;
  - последнего **входящего** сообщения WhatsApp от клиента.

  Если клиент сам написал, он «на связи», и предлагать «Минус» нельзя.
  (моё решение)
- **«Перенести»** закрывает задачу с `result='rescheduled'` и создаёт новую
  того же типа на выбранное время, так в ленте видна история переносов.
- **Переход лида в `won`/`lost` и архивирование** (включая «Не лид» из
  WhatsApp) закрывают все открытые задачи (`status='canceled'`,
  `result='auto_canceled'`). Если лид вернули в работу, задачи не
  восстанавливаются: лид показывает «Нет задачи», и человек ставит новую.
  (моё решение)
- **Задача без ответственного** (сотрудника удалили, или при переносе не
  нашлось ответственного) видна администраторам и основателям в «Моих задачах»
  в группе «Без ответственного». Завершить или переназначить её может любой с
  правом ставить задачи. (моё решение)
- **Старое «следующее действие».** Миграция переносит у активных лидов
  `next_action_type` / `next_action_at` в задачи:
  - `kind='call'` (`'other'`, если в тексте нет «звон»);
  - ответственный — сеттер, иначе клоузер;
  - у кого нет ни того, ни другого, — задача без ответственного (см. выше).

  Детали (мои решения):
  - Переносятся только **открытые** лиды: `status=active` и этап не
    `won`/`lost`.
  - Нет даты (`next_action_at` пуст) — задача не создаётся, текст
    дописывается в комментарий лида: «Было запланировано: …».
  - Дата в прошлом — срок переносится на **день миграции, 10:00 по Бишкеку**,
    в комментарий задачи пишется «перенесено из «следующего действия» от
    дд.мм». Иначе в первый день у всех будет лавина давно просроченных задач.
  - Дата в будущем — как есть.

  После этого поля не показываются и не редактируются (колонки остаются как
  legacy, по образцу `potential_amount`). Аналитика (`services/analytics.py`,
  «без следующего действия» / «просрочено») и `LeadListView` переходят на
  задачи.

### 5.2 Права

- Ставить задачи по лиду могут те же, кто работает с WhatsApp
  (`can_use_whatsapp`: admin, основатели, клоузеры, участники отдела «Продажи»).
- Ответственным можно назначить любого из этого круга.
- Завершать, переносить и отменять задачу могут ответственный, автор, admin и
  основатели. Остальные видят задачу, но кнопок у них нет.

### 5.3 Лента событий

`GET /api/leads/{id}/feed?before=<cursor>&limit=50` — события в обратном
хронологическом порядке, порциями. На клиенте лента показывается сверху вниз от
старых к новым, как в мессенджере. Чтобы подгрузить ранние события, нужно
прокрутить вверх.

Источники, сведённые в один формат `{type, at, actor, data}`:

| Источник | `type` |
|---|---|
| сообщения WhatsApp (чат лида) | `message` |
| `lead_activities` (касания, примечания) | `activity` / `note` |
| `lead_stage_history` | `stage` |
| `meetings` | `meeting` |
| `lead_tasks` — создание и завершение | `task_created` / `task_done` |
| `lead_files` | `file` |
| подтверждённые оплаты (`deal_payments`, как в нынешнем таймлайне) | `payment` |
| создание лида | `created` |

- **Права в ленте** (моё решение). Сообщения WhatsApp (`message`) попадают в
  ленту только тем, у кого есть доступ к переписке (`can_use_whatsapp`).
  Остальные видят ленту без переписки, как сейчас не видят чат. Непрочитанные
  обнуляет только запрос пользователя с доступом.
- Записи `LeadActivity` типа `stage_change` в ленту не выводятся, потому что
  этапы уже приходят из `lead_stage_history` (без дублей).
- Причина отказа «Не выходит на связь» добавляется в справочник, если её нет
  (seed и миграция).

- Примечание сохраняется как `LeadActivity` с `activity_type='note'`.
- Существующий `get_lead_timeline` (`services/leads.py`) — база, его
  расширяем. Блоки «Этапы сделки», «История касаний», «Таймлайн» и отдельный
  чат из карточки уходят.

Открытые задачи отдаются отдельно (`GET /api/leads/{id}/tasks?status=open`) и
закреплены над лентой.

### 5.4 API задач

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/leads/{id}/tasks?status=open\|all` | задачи лида |
| `POST` | `/api/leads/{id}/tasks` | создать: `{kind, due_at, assignee_id?, comment}` |
| `POST` | `/api/lead-tasks/{id}/complete` | `{result: connected\|no_answer\|done, note?}` → задача, `no_answer_streak` лида, `suggest_lost: bool` (серия ≥ 5) |
| `POST` | `/api/lead-tasks/{id}/reschedule` | `{due_at}` → новая задача |
| `POST` | `/api/lead-tasks/{id}/cancel` | |
| `GET` | `/api/lead-tasks?assignee=me\|<id>&scope=overdue\|today\|upcoming` | «Мои задачи» |

### 5.5 Карточка лида (раскладка A)

```
┌ Шапка: Имя · телефон · [этапы-полоса, клик = переход] · [Перевести ▾] [⋯ Изменить / Архив]
├ Левая колонка (≈35%)                 │ Правая колонка
│  Сеттер / Клоузер / Источник /       │  ┌ Открытые задачи (закреплены, просроченные — красные)
│  Услуга / Сумма сделки / Оплачено    │  │  📞 Позвонить · сегодня 15:00  [✅ Дозвонился] [📵 Недозвон] [🕒 Перенести]
│  📵×N, если есть серия               │  ├ Лента (WhatsApp, примечания, касания, этапы, встречи, задачи, файлы)
│  ▸ Финансы и график оплат (свёрнуто) │  │  … прокрутка вверх — раньше
│  ▸ Встречи (N)                       │  └ Поле ввода: [WhatsApp] [Примечание] [Задача]
│  ▸ Файлы (N)                         │
│  ▸ Проект в разработке (если есть)   │
```

- **Шапка.** Остаются «Перевести ▾» (существующий список переходов) и меню «⋯»
  («Изменить», «Архив», «Добавить касание», «Загрузить файл»). «Провести
  оплату» показывается в шапке только на этапах «Договор» / «Ожидание оплаты»,
  как сейчас.
- **Вкладка «WhatsApp»** видна, только если у пользователя есть доступ (уже
  есть `GET /api/whatsapp/access`). По умолчанию открыта она, если у лида есть
  чат, иначе «Задача».
- **Вкладка «Задача».** Чипы типа, чипы быстрого времени («через 15 мин»,
  «через 1 час», «сегодня вечером» = 18:00, «завтра утром» = 10:00 следующего
  дня, всё по Бишкеку), «дата и время…», ответственный (по умолчанию я),
  комментарий.
- **После «Недозвон»** прямо в блоке задачи появляется строка «Поставить:
  📞 Перезвонить · через 2 часа [Поставить] [другое время] [не надо]». При
  серии ≥ 5 рядом подсказка «5 недозвонов подряд — перевести в «Минус» (не
  выходит на связь)?», которая открывает существующую форму перехода с
  выбранной причиной.
- **После «Дозвонился»** — поле «Итог звонка» (необязательное) и строка
  «Следующий шаг: [сменить этап ▾] [поставить задачу]».
- **«Нет задачи».** Если у открытого лида нет открытых задач, над лентой
  жёлтая плашка «Нет следующей задачи — поставьте» с фокусом на вкладке
  «Задача».
- **Узкий экран** (< 900px): колонки друг под другом, правая первой.
- Существующие компоненты (`PaymentScheduleSection`, `TransitionModal`,
  `EditLeadModal`, `AddActivityModal`, загрузка файла) переиспользуются, меняется
  только место.

### 5.6 Страница «Мои задачи» (`/tasks`, пункт меню в «Отдел продаж»)

- Группы «Просрочено» (красные) / «Сегодня» / «Завтра и позже».
- Строка: время, тип, клиент (ссылка на лида), комментарий и те же кнопки
  результата.
- Руководитель (admin, основатели) видит фильтр «Ответственный».

### 5.7 Доска и колокольчик

- **Карточка на доске:**
  - ⏰ ближайшая задача (время; красное, если просрочена);
  - жёлтое «Нет задачи», если открытых нет;
  - 📵×N при серии недозвонов;
  - `CardOut` получает `next_task: {id, kind, due_at, overdue} | None`,
    `no_answer_streak: int`. Считается батч-запросами, без N+1.
- **Сортировка** (`board_sort_key`): непрочитанные WhatsApp → просроченная
  задача → нет задачи → последняя активность (так и было задумано в §5.2
  исходного дизайна).
- **Быстрые фильтры доски:** добавить «Просрочено» и «Без задачи».
- **Колокольчик** — для ответственного «Через 15 минут: <задача> — <клиент>»
  и «Просрочено: <задача> — <клиент>». Пункты 6 («просроченное следующее
  действие») и 7 («без следующего действия») переписываются на задачи.
  Логика — в одной функции `services/reminders.py::due_reminders(db, user)`,
  чтобы позже её же использовал Telegram-бот.

## 6. Что оставлено строителю

- Вёрстка и стили — в духе текущего интерфейса (`components/ui`).
- Формат курсора ленты (рекомендация: `at` + тип + id).
- Размер порции ленты (50) и интервал обновления карточки (сейчас чат
  опрашивается раз в 5 с; ленту обновлять так же, только последние события).
- Миграция `026` (`lead_tasks` + перенос `next_action`) с проверкой на
  PostgreSQL 16.
- Обновление MCP-инструментов лидов, если они читают `next_action_*`.
- Документация: README, product-spec, DEPLOY.
