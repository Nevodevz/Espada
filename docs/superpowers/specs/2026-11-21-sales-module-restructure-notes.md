# Перестройка модуля отдела продаж — заметки обсуждения (не утверждено)

Статус: идёт обсуждение. Вариант структуры ещё не выбран, дизайн-документа нет.

## Запрос владельца

«Давай разберем весь модуль отдела продаж. Мне не нравится. Как можно его улучшить?
Может стоит переделать его структуру, какие-то лишние элементы возможно есть?»

Что не нравится (словами владельца): дублирующиеся моменты, местами структура,
и «ещё есть вещи, но я не могу их описать».

## Рабочий день (со слов владельца, примерно)

- **Сеттер:** приходит, заходит в систему, смотрит свои задачи с прошлых дней, новых и
  старых лидов. Обрабатывает новых лидов (текст, звонок), меняет статусы, назначает
  встречи с учётом свободных окошек.
- **Клоузер:** главное — встречи. Смотрит календарь и работает по нему.

## Как устроено сейчас (меню «Отдел продаж», `frontend/src/components/Shell.tsx` SALES_SUBNAV)

| Пункт | Адрес | Что там |
|---|---|---|
| Лиды и воронка | `/leads` | 16 карточек цифр в два ряда (часть повторяется) + фильтры + список |
| Доска | `/leads/board` | доска этапов (фильтры: мои, без ответственного, просроченные, без задачи) |
| Мои задачи | `/tasks` | задачи по лидам: просрочено / сегодня / позже |
| Встречи | `/dept/sales?meetings=1` | та же страница, что «Дневник», открывает модалку-таблицу встреч |
| Дневник | `/dept/sales` | `SalesDepartmentView`: ручной дневник сеттеров (настраиваемые колонки), календарь встреч, сводка, модалка встреч |

Плюс рядом: `/analytics` (ещё 16 карточек, частично про продажи), `/kpi` (план/факт),
`/reports`, карточка лида `/leads/[id]`, `/admin/whatsapp`, колокольчик.

## Найденные дубли

- «Встречи» и «Дневник» — одна страница.
- Встреча видна в 4 местах: этап «Встреча», задача типа «Встреча», календарь, таблица встреч.
- Цифры продаж в 4 местах: `/leads`, сводка Дневника, `/analytics`, `/kpi`.
- Список и доска — одни лиды, разные страницы и фильтры.
- Дневник заполняется вручную, хотя звонки (дозвон/недозвон), лиды, WhatsApp и встречи
  CRM уже собирает сама.
- При переводе лида во «Встречу» сеттер не видит занятость клоузера — окна приходится
  искать в календаре отдельно.

## Предложенные варианты (макеты показывались)

- **А (рекомендован).** Меню по рабочим задачам, 4 пункта:
  - «Сегодня» — старт сеттера: просроченные/сегодняшние задачи, новые необработанные лиды,
    неотвеченные WhatsApp (заменяет «Мои задачи»);
  - «Лиды» — одна страница, переключатель Доска/Список, общие фильтры, без 16 карточек;
  - «Встречи» — календарь на всю страницу (экран клоузера), таблица переключателем,
    фильтр по клоузеру; при назначении встречи из лида видны свободные окна;
  - «Показатели» — для руководителя: воронка + сводка по сотрудникам, считается
    автоматически; продажные цифры уходят из «Аналитики» (там остаются CPL, CAC, финансы).
  Минус: самая большая работа.
- **Б.** Точечная уборка: «Встречи» на свою страницу, один ряд цифр на «Лидах»,
  Доска/Список переключателем. Дневник ручной, экрана «Сегодня» нет.
- **В.** Всё на одном экране: доска + боковая панель «Задачи / Календарь». Риск перегруза,
  на который владелец уже жаловался.

## Открытые вопросы

- Какой вариант (или комбинация) берём.
- Что делать с ручным Дневником: убрать, заменить автосводкой, оставить только
  неавтоматизируемые колонки.
- Судьба `/analytics` и `/kpi` относительно «Показателей».
- Нужна ли клоузеру своя стартовая «Сегодня» или ему хватит «Встреч».
